# RAG Notes Bot

## Обзор

RAG Notes Bot — Telegram-бот для семантического поиска и генерации ответов по личным заметкам, реализованный на архитектуре RAG (Retrieval-Augmented Generation). В отличие от классического полнотекстового поиска, бот понимает смысл запроса и находит релевантные фрагменты даже при использовании синонимов, перефразирований и контекстно близких формулировок. Пользователь загружает заметки в форматах Markdown, PDF или TXT, после чего может задавать вопросы на естественном языке и получать ответы, основанные исключительно на содержимом загруженных документов.

---

## Цель проекта

С ростом объёма личных заметок классический поиск по ключевым словам (Full-Text Search) становится неэффективным: он не учитывает синонимы, контекст и смысловую близость понятий. Цель проекта — разработать прикладное решение, которое позволяет пользователю взаимодействовать со своей базой знаний в формате естественного диалога. Система должна:

- Находить семантически релевантные фрагменты заметок по смыслу, а не по точному совпадению слов
- Генерировать связные, точные ответы на основе найденного контекста через LLM
- Работать с русскоязычным контентом без потери качества поиска
- Быть доступной через интерфейс Telegram без необходимости установки дополнительного ПО

## Поддерживаемые функции

### Управление заметками

| Команда / Действие | Описание |
|---|---|
| Отправить файл боту | Загрузка и индексирование заметки (MD, PDF, TXT) |
| `/upload` | Явная команда загрузки файла |
| `/stats` | Статистика индекса: количество векторов, источники, параметры |
| `/clear` | Очистка FAISS-индекса с подтверждением через Inline Keyboard |

### Семантический поиск и генерация

| Команда / Действие | Описание |
|---|---|
| Написать вопрос в чат | Автоматический запуск полного RAG-пайплайна |
| `/ask <вопрос>` | RAG-запрос: поиск top-3 чанков + генерация ответа через GPT |
| `/search <запрос>` | Только семантический поиск без генерации (возвращает фрагменты с оценкой сходства) |
| `/help` | Справка по командам и форматам файлов |

### Поддерживаемые форматы

- **Markdown** (`.md`, `.markdown`) — заметки Obsidian, Notion, Typora; секционирование по заголовкам H1/H2
- **PDF** (`.pdf`) — статьи, книги; извлечение текста постранично через `pypdf`
- **Plain Text** (`.txt`) — обычный текст; автоопределение кодировки (UTF-8, CP1251, Latin-1)

## Технологический стек

### Модель эмбеддингов

Выбрана модель `intfloat/multilingual-e5-base` по следующим причинам:

- Нативная поддержка русского языка (обучена на 100+ языках)
- Свободная лицензия (MIT), возможность локального запуска без API-ключей
- Размер модели ~270 MB

## Архитектура проекта

### Структура модулей

```md
rag-notes-bot/
├── bot/
│   ├── main.py          # Точка входа: Application PTB, регистрация хэндлеров
│   ├── handlers.py      # Обработчики команд и сообщений
│   └── middleware.py    # Логирование, Rate Limiting, декораторы
│
├── rag/
│   ├── vector_store.py  # FAISS-индекс + E5Embeddings (персистентный)
│   ├── retriever.py     # Семантический поиск, RetrievedChunk, форматирование
│   ├── generator.py     # Асинхронный вызов llama3
│   └── pipeline.py      # RAG-оркестрация: retrieve → generate
│
├── ingestion/
│   └── parser.py        # Парсинг MD/PDF/TXT → List[Document] → чанки
│
├── models/
│   └── multilingual-e5-base/   # Локальная копия модели (~270 MB)
│
├── data/
│   ├── faiss_index/     # Персистентный FAISS-индекс (index.faiss + index.pkl)
│   └── notes/           # Опциональная папка для заметок
│
├── tests/
│   ├── test_parser.py   # Тесты парсинга и чанкинга
│   └── test_retriever.py # Тесты ретривера с mock VectorStore
│
├── config.py            # Dataclass конфигурации из .env
├── requirements.txt
├── Dockerfile
├── docker-compose.yml
└── .env
```

### Слои системы

Архитектура разделена на четыре независимых слоя:

**1. Telegram Interface Layer** (`bot/`)
Принимает обновления от Telegram через polling или webhook. Хэндлеры делегируют бизнес-логику в RAG-слой и форматируют ответы для отображения в Markdown. Middleware обеспечивает логирование, rate limiting и авторизацию через декораторы.

**2. Ingestion Layer** (`ingestion/`)
Парсит входящие файлы в список `Document` (LangChain), очищает Markdown-разметку, извлекает текст из PDF постранично, определяет кодировку TXT-файлов. Затем `RecursiveCharacterTextSplitter` нарезает документы на перекрывающиеся чанки с заданным `chunk_size` и `chunk_overlap`.

**3. Retrieval Layer** (`rag/vector_store.py`, `rag/retriever.py`)
`VectorStore` хранит чанки в FAISS-индексе с HuggingFace-эмбеддингами. `Retriever` принимает текстовый запрос, генерирует его эмбеддинг (с префиксом `query:`), выполняет ANN-поиск, конвертирует L2-расстояние в оценку сходства [0..1], фильтрует по `min_score` и дедуплицирует результаты.

**4. Generation Layer** (`rag/generator.py`, `rag/pipeline.py`)
`Generator` формирует промпт с системными инструкциями и найденным контекстом, выполняет асинхронный запрос к llama3. `RAGPipeline` оркестрирует весь поток: вопрос → ретрив → генерация → ответ + источники.

## Пайплайн генерации ответов

### Полный поток (команда `/ask` или текстовое сообщение)

```md
┌─────────────────────────────────────────────────────────────┐
│  1. ПОЛЬЗОВАТЕЛЬ: "Что такое механизм attention?"           │
└─────────────────────────┬───────────────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────────┐
│  2. TELEGRAM HANDLER (handlers.py)                          │
│     • Получает текст сообщения                              │
│     • Проверяет что индекс не пуст (store.is_empty)         │
│     • Отправляет "⏳ Генерирую ответ…"                      │
└─────────────────────────┬───────────────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────────┐
│  3. EMBEDDER (E5Embeddings)                                 │
│     • Добавляет префикс: "query: Что такое attention?"      │
│     • SentenceTransformer.encode() → вектор 768-мерный      │
│     • normalize_embeddings=True → единичная длина           │
└─────────────────────────┬───────────────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────────┐
│  4. FAISS ANN-ПОИСК (VectorStore)                           │
│     • similarity_search_with_score(query_vec, k=3)          │
│     • Возвращает top-3 пары (Document, L2_distance)         │
│     • L2 → similarity: score = 1 / (1 + distance)           │
└─────────────────────────┬───────────────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────────┐
│  5. RETRIEVER (retriever.py)                                │
│     • Фильтрация по min_score                               │
│     • Дедупликация одинаковых фрагментов                    │
│     • Сортировка по убыванию score                          │
│     • Формирование контекста:                               │
│       [ml_notes.md | стр. 3 | сходство: 89%]                │
│       Attention — механизм взвешивания токенов...           │
└─────────────────────────┬───────────────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────────┐
│  6. GENERATOR (generator.py) — llama3.                      │
│     System prompt:                                          │
│       "Отвечай ТОЛЬКО на основе контекста.                  │
│        Если ответа нет — скажи об этом явно."               │
│     User message:                                           │
│       "Контекст:\n[фрагменты]\n\nВопрос: <запрос>"          │
│     → Асинхронный вызов gpt-4o-mini                         │
└─────────────────────────┬───────────────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────────┐
│  7. TELEGRAM RESPONSE                                       │
│     • Текст ответа от GPT (до 4096 символов)                │
│     • Футер с источниками:                                  │
│       📎 Источники: `ml_notes.md`, `transformers.pdf`       │
└─────────────────────────────────────────────────────────────┘
```

### Ключевые параметры качества

| Параметр | Значение | Влияние на качество |
|---|---|---|
| `chunk_size` | 500 символов | Больше → больше контекста в чанке, но шумнее поиск |
| `chunk_overlap` | 50 символов | Предотвращает потерю смысла на границах чанков |
| `top_k` | 3 | Кол-во фрагментов в промпте GPT |
| `min_score` | 0.0 (настраивается) | Порог отсечения нерелевантных результатов |
| E5-префиксы | `query:` / `passage:` | Критично для качества — без них метрика деградирует |
| `normalize_embeddings` | `True` | Переводит L2-поиск в косинусный |
